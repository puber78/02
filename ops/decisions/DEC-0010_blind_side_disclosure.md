# DEC-0010｜盲侧完整性披露（EXAM04 前置条件未满足）

- 日期：2026-11-02
- 状态：披露（不修复、不洗白）
- 关联：PREDICTION04、RESULT04、EXAM05

## 事实

大纲 EXAM04 要求"评价角色完成 T_pilot 推理并隔离存放；开发方在全部选择、分析代码和
主要对比冻结前不得看到 T_pilot 评分、质量分布或可用于调参的诊断"。

本项目的实际执行顺序是：

1. **EXAM02**：实拍 1000 张 → 逐帧 QC（读 T_pilot 帧）→ 评分（读 T_pilot 分数）→ 池化 AUC。
2. **EXAM03**：数字族与选择（`S_dig` 只读 C_pool；**未读** T_pilot 数字）。
3. **EXAM04**：同源配对（读 T_pilot 分数与数字）。

因此，在做任何选择/分析冻结之前，执行者**已经**看过 T_pilot 的实拍分数、QC 指标与
池化 AUC。EXAM04 的"盲侧"前提在事实上不成立。

## 处理

1. `predictions/PREDICTION04.yaml` 标 `RETROSPECTIVE_RECORD` 并写明披露段；
   不伪造更早时间戳。
2. `reports/RESULT04.md` 增加"盲侧完整性"一节。
3. 论文的 Limitations 必须写明：EXAM02 的 QC 与池化 AUC 先于 EXAM04，因此
   EXAM04/05 的结论属于**先导（PILOT）**证据；确认性主张必须走 EXAM07 的新来源。
4. 已发生的分析内容不回改；后续阶段（EXAM05–09）只能在前向设计上尽量补救
   （例如 EXAM07 用未接触过的新来源做确认）。

## 为什么不重做

重做需要重新采集 T_pilot 或换新来源，成本数百张；而大纲本身为 EXAM07 预留了
"独立来源上的确认性评价"。把已污染的先导阶段如实标记、把确认性证据交给新来源，
比伪装盲侧更符合"不打折扣"的要求。

## 教训（写入方法记录）

- "不读 T_pilot" 必须在**数据层**实现（隔离目录 + 访问计数），不能只靠执行者自律。
- 阶段依赖是串行的：EXAM02 的 QC 天然会接触评价集，所以在依赖链里 EXAM04 不可能真正盲。
- 若要满足盲侧，正确顺序是：先冻结选择（EXAM03），再对 T_pilot 做一次性、不可回看的评价，
  并且评价者与开发者分离。
